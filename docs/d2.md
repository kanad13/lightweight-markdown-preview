# D2 Diagrams in the Preview

This page is the guide and the gallery for D2 in the Lightweight Markdown Preview.

- **What D2 is:**
  - [D2](https://d2lang.com) is a text language for architecture diagrams.
  - You write boxes, containers and arrows, and a renderer draws them.
- **What the preview adds:**
  - GitHub and VS Code do not draw D2.
  - The preview draws every ` ```d2 ` fence next to the file you edit.
- **How this page works:**
  - Each example shows the D2 source, then the picture it draws.
  - In the preview, every source block turns into a live diagram once you finish the setup below.
  - A pre-drawn copy follows each block, so readers on GitHub see the pictures too.

## A network in one diagram

- **What it shows:**
  - Nested containers: region, VPC, zones and subnets.
  - A grid that puts two zones side by side.
  - Shapes for people and databases.
  - A dashed edge for replication.

```d2
vars: {
  d2-config: {
    layout-engine: tala
    pad: 24
  }
}

users: Users {
  shape: person
}
corp: Data center {
  vpn: Customer gateway
}

aws: AWS eu-west-1 {
  cdn: CloudFront
  assets: S3 static assets {
    shape: cylinder
  }
  vpc: VPC 10.0.0.0/16 {
    alb: Load balancer
    vgw: VPN gateway
    zones: "" {
      grid-columns: 2
      style: {
        fill: transparent
        stroke: transparent
      }
      a: Zone a {
        app: App subnet {
          svc: App servers
        }
        data: Data subnet {
          db: Primary database {
            shape: cylinder
          }
        }
      }
      b: Zone b {
        app: App subnet {
          svc: App servers
        }
        data: Data subnet {
          db: Standby database {
            shape: cylinder
          }
        }
      }
    }
  }
}

users -> aws.cdn: HTTPS
aws.cdn -> aws.assets: static
aws.cdn -> aws.vpc.alb: dynamic
aws.vpc.alb -> aws.vpc.zones.a.app.svc
aws.vpc.alb -> aws.vpc.zones.b.app.svc
aws.vpc.zones.a.app.svc -> aws.vpc.zones.a.data.db: SQL
aws.vpc.zones.b.app.svc -> aws.vpc.zones.a.data.db: SQL
aws.vpc.zones.a.data.db -> aws.vpc.zones.b.data.db: replication {
  style.stroke-dash: 4
}
corp.vpn <-> aws.vpc.vgw: VPN
```

![A D2 diagram of an AWS network: users reach CloudFront, a load balancer in a VPC sends requests to app servers in two availability zones, which use a primary database replicated to a standby, with a VPN to a data center](d2/network.svg)

## Set it up in three steps

1. **Start a renderer.** Run a Docker container on your machine, so your diagrams stay private:

   ```bash
   docker run -d --name d2-renderer -p 8080:8080 ghcr.io/kanad13/d2-renderer:latest
   ```

   The image runs natively on Intel, AMD and Apple Silicon, with no `--platform` flag.

2. **Choose it.** Run **Markdown: Choose D2 Renderer** from the Command Palette and pick **Local Docker container**.

   ![The Choose D2 Renderer quick pick with four choices: a local Docker container, the Kroki public service, another URL, and turning D2 off](../assets/readme-d2-choose-renderer.png)

3. **Write a diagram** in a ` ```d2 ` fence, and open the preview.

- **Before step 2:**
  - A D2 fence stays an ordinary code block, with one quiet hint under the first one.
  - Documents without D2 look exactly as before.

## More examples

### A message flow

- **What it shows:** a sequence diagram with a labeled group for the retry.

```d2
vars: {
  d2-config: {
    pad: 24
  }
}

shape: sequence_diagram

customer
orders
payments
warehouse

customer -> orders: place order
orders -> payments: charge card
payments -> orders: receipt
orders -> warehouse: reserve stock
warehouse -> orders: confirmed
orders -> customer: confirmation email

payment retry: {
  orders -> payments: charge again
  payments -> orders: declined
}
```

![A D2 sequence diagram: a customer places an order, orders charges payments and reserves stock with the warehouse, and a payment retry group shows a second charge and a decline](d2/sequence.svg)

### A database schema

- **What it shows:** tables with typed columns and keys, and foreign keys drawn as arrows between columns.

```d2
vars: {
  d2-config: {
    layout-engine: tala
    pad: 24
  }
}

customers: {
  shape: sql_table
  id: int {constraint: primary_key}
  email: varchar {constraint: unique}
  created_at: timestamp
}
orders: {
  shape: sql_table
  id: int {constraint: primary_key}
  customer_id: int {constraint: foreign_key}
  status: varchar
  total: decimal
}
order_items: {
  shape: sql_table
  order_id: int {constraint: foreign_key}
  product_id: int {constraint: foreign_key}
  quantity: int
}
products: {
  shape: sql_table
  id: int {constraint: primary_key}
  name: varchar
  price: decimal
}

orders.customer_id -> customers.id
order_items.order_id -> orders.id
order_items.product_id -> products.id
```

![Four SQL tables: products, order_items, orders and customers, with arrows from the foreign key columns to the primary keys they reference](d2/schema.svg)

### A class diagram

- **What it shows:** classes with fields and methods, with inheritance and composition.

```d2
vars: {
  d2-config: {
    layout-engine: tala
    pad: 24
  }
}

Payment: {
  shape: class
  +id: UUID
  +amount: Money
  +authorize(): Result
  +refund(): Result
}
CardPayment: {
  shape: class
  -token: String
  +authorize(): Result
}
BankTransfer: {
  shape: class
  -iban: String
  +authorize(): Result
}
Order: {
  shape: class
  +lines: List
  +total(): Money
}

CardPayment -> Payment: extends {
  target-arrowhead.shape: triangle
}
BankTransfer -> Payment: extends {
  target-arrowhead.shape: triangle
}
Order -> Payment: pays with {
  target-arrowhead.shape: diamond
}
```

![A D2 class diagram: CardPayment and BankTransfer extend Payment, and Order holds a Payment](d2/classes.svg)

## Choose a renderer

- **The setting:**
  - `lightweightMarkdownViewer.d2.rendererUrl` holds the base URL of a Kroki-compatible renderer.
  - The preview asks that renderer for each diagram.

| Renderer            | URL                     | Notes                                                                                                                                                                                           |
| :------------------ | :---------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Local Docker**    | `http://localhost:8080` | Runs D2 0.9.0 on your machine, so your diagram text stays there. Every example on this page draws with it. Source: [d2-renderer](https://github.com/kanad13/d2-renderer).                       |
| **Kroki**           | `https://kroki.io`      | A public service with nothing to install, handy for a first try. It receives your diagram text, and it runs D2 0.7.1, so the examples that name `layout-engine: tala` need the Docker renderer. |
| **Your own server** | Your `https://` URL     | Run the d2-renderer image on any container host. Its repository includes a runbook that deploys it to Google Cloud Run from GitHub Actions.                                                     |

- **Privacy:**
  - The extension has no telemetry.
  - Diagram text goes only to the renderer you choose.
- **Plain `http://`:**
  - Use it for `localhost` or a network you trust.
  - The diagram text travels in the address.
- **Your setting only:**
  - `rendererUrl` is a user setting.
  - A repository you clone cannot choose where your diagrams go.

## Put options in the diagram

- **Where options live:**
  - D2 keeps layout, style and padding in the diagram, in `d2-config`.
  - The extension adds no layout or style settings of its own.
  - The picture then looks the same in the preview, in the playground and on a teammate's machine.

```d2
vars: {
  d2-config: {
    layout-engine: elk
    sketch: true
    pad: 24
  }
}

client -> server: request
server -> database: query
```

![A D2 diagram drawn in a hand-drawn style: a client sends a request to a server, which queries a database](d2/options.svg)

- **Padding:**
  - `pad: 24` trims the 100-pixel margin that D2 adds around every diagram.
  - The picture then fills the preview.
- **Theme:**
  - The extension sets the theme for you, so diagrams match the editor.
  - Light editor themes use D2 theme 0, and dark ones use Dark Mauve (200).
  - A `theme-id` in the diagram is replaced.

## Write diagrams that read well

- **Width:**
  - The preview column is about 860 pixels wide, and wider diagrams scale down.
  - Containers, grids and `direction: down` keep a diagram compact.
- **Size:**
  - Keep one diagram under about a thousand lines.
  - The address that carries the source has a limit of 8,000 characters.
  - A larger diagram shows its source with a note to split it.
- **Icons and links:**
  - The renderer embeds `icon:` images into the picture, so icons show.
  - Tooltips and links need a live page, and a picture has none.
- **Edits:**
  - On the Docker renderer, only the diagram you change asks for a new picture.

## If a diagram does not draw

![A syntax error shown as a message and the diagram source, between two diagrams that drew correctly](../assets/readme-d2-failure.png)

| What you see                                                    | What to do                                                                                                                   |
| :-------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------- |
| The D2 source in a code block, with "This is a D2 diagram"      | Run **Markdown: Choose D2 Renderer**.                                                                                        |
| A yellow box: "The D2 renderer URL is not usable"               | Set a plain `http://` or `https://` URL, with no user name, query or fragment.                                               |
| A yellow box: "This D2 diagram did not render", with the source | Check that the renderer is running and the URL is right, then fix the diagram. The D2 playground shows the compiler message. |
| A note that the diagram is too large to send                    | Split it into smaller diagrams.                                                                                              |

## Related projects
