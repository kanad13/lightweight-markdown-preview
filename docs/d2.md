# D2 Diagrams in the Preview

This guide shows how to draw [D2](https://d2lang.com) diagrams in the Lightweight Markdown Preview: what D2 is, how to pick a renderer, which settings exist and why they have their defaults, and what to do when a diagram does not draw.

## What D2 Is

D2 is a text language for diagrams. You describe boxes, containers and arrows, and a layout engine draws them. It is built for software architecture, so it handles nested containers (a cloud, a network, a subnet), database tables, sequence diagrams and classes. GitHub and VS Code do not draw D2, so this extension draws each ` ```d2 ` fence through a renderer that you choose.

- **Learn the language:** the [D2 tour](https://d2lang.com/tour/intro) teaches it, and the [playground](https://play.d2lang.com) runs it in a browser.
- **Try a diagram here:** open [examples/d2.md](../examples/d2.md) after you set up a renderer.

## Set It Up in Three Steps

1. **Start a renderer.** The quickest private choice is a Docker container on your machine:

   ```bash
   docker run -d --name d2-renderer --platform linux/amd64 -p 8080:8080 ghcr.io/kanad13/d2-renderer:latest
   ```

   The image is published for `linux/amd64` only. The `--platform` flag makes Apple Silicon Macs run it under emulation, and it changes nothing on Intel machines. Without the flag, an Apple Silicon Mac answers "no matching manifest".

2. **Tell the extension where it is.** Run **Markdown: Choose D2 Renderer** from the Command Palette and pick **Local Docker container**.
3. **Write a diagram.**

   ````markdown
   ```d2
   direction: right
   clients -> gateway: HTTPS
   gateway -> orders: REST
   orders -> db: SQL
   ```
   ````

Until you do step 2, a D2 fence stays an ordinary code block with one quiet line under the first one. Documents without D2 never change.

## Choose a Renderer

The setting `lightweightMarkdownViewer.d2.rendererUrl` holds the renderer's base URL. The preview asks `<URL>/d2/svg/<payload>` for each diagram, where the payload is the compressed D2 source. This is the address format that [Kroki](https://kroki.io) uses, so any Kroki-compatible server works.

| Option               | URL                     | Where your diagram text goes | Notes                                                                                                                                                            |
| :------------------- | :---------------------- | :--------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Local Docker**     | `http://localhost:8080` | Your machine only            | D2 0.9.0 with dagre, ELK and TALA. Source and image: [d2-renderer](https://github.com/kanad13/d2-renderer).                                                      |
| **Kroki, to try it** | `https://kroki.io`      | A third-party public service | Nothing to install. It runs D2 0.7.1 at the time of writing, which has no TALA, and complex diagrams come out less tidy. Use it to try D2, not for private text. |
| **Your own server**  | Your `https://` URL     | The server you run           | Run the d2-renderer image on any container host. The repository documents Cloud Run and Fly.io.                                                                  |

- **Privacy:** the extension has no telemetry. Diagram text goes only to the renderer you choose.
- **Plain `http://`:** use it for `localhost` or a network you trust. The diagram text travels in the URL, readable by anything on the path.
- **Where the setting lives:** it is a user setting. A repository cannot set it, so a cloned project cannot choose where your diagrams go.
- **Hosting for other people:** D2 fetches `icon:` URLs on the server when it draws a diagram, and the d2-renderer image does so for any address, including private ones. Do not expose a renderer to authors you do not trust on a network that has internal services.

## Settings and Defaults

| Setting                                    | Default | Why this default                                                                                                                                                                                                      |
| :----------------------------------------- | :------ | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `lightweightMarkdownViewer.d2.rendererUrl` | empty   | Sending text to a service nobody chose would break the privacy promise, and a preset `localhost` address fails on most machines. Empty keeps every document as it was.                                                |
| `lightweightMarkdownViewer.d2.layout`      | `dagre` | Every D2 build and every renderer has it, and a small edit moves little. TALA is open source and often tidier for architecture, but it is missing on Kroki and a one-node edit can reshuffle a whole diagram.         |
| `lightweightMarkdownViewer.d2.sketch`      | `false` | Clean diagrams are easier to read and to compare. Turn it on for a hand-drawn look.                                                                                                                                   |
| Theme, not a setting                       | follows | Light themes use D2 theme 0 (Neutral Default). Dark themes and the dark high-contrast theme use theme 200 (Dark Mauve). An image cannot follow VS Code's theme by itself, so the extension picks one for each render. |

## Layout Engines

| Engine  | Strength                                                   | Cost                                                                                                                   |
| :------ | :--------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------- |
| `dagre` | Fast, stable, in every renderer. Good for flows.           | Layered, so deep nesting looks plain.                                                                                  |
| `elk`   | Orthogonal routing, good for dense graphs.                 | Wider output; the picture scales down to fit the preview.                                                              |
| `tala`  | Built for architecture: nested containers, grids, routing. | Needs D2 0.9.0 or later. It is randomized, so adding one node can change the whole layout. It slows on large diagrams. |

TALA became open source under the same license as D2, MPL-2.0, in D2 0.9.0 ([announcement](https://d2lang.com/blog/tala-is-open-source/)). Select it with `lightweightMarkdownViewer.d2.layout`, or inside one diagram:

```d2
vars: {
  d2-config: {
    layout-engine: tala
  }
}
```

A diagram that names `tala` fails on a renderer without it (Kroki answers "tala is not bundled"), so name it only when every reader uses a renderer that has it.

## Write Diagrams That Read Well in a Preview

- **Trim the margin.** D2 pads every diagram by 100 pixels. Add `vars: { d2-config: { pad: 24 } }` to the diagram and the picture fills the preview. Kroki and the d2-renderer image both honor it.
- **Mind the width.** The preview column is about 860 pixels wide. A diagram that is much wider scales down until its text is small. Group nodes in containers, use `direction: down`, or split the diagram.
- **Keep the source short enough.** The preview does not send a diagram whose address would pass 8,000 characters. That is roughly a thousand lines of ordinary D2, so only very large diagrams reach it. Split those.
- **Let the theme choose colors.** The extension sends the theme with each request, and on the d2-renderer image it overrides a `theme-id` in the diagram. Fixed fills can lose contrast in the other color scheme.
- **Icons work, interaction does not.** The renderer embeds `icon:` images into the picture, so they show, as long as the renderer can reach them. Tooltips and links need a live page, and an image has none.

## When a Diagram Does Not Draw

| What you see                                                    | Cause and fix                                                                                                                                                                                                |
| :-------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The D2 text as a code block with "This is a D2 diagram..."      | No renderer is set. Run **Markdown: Choose D2 Renderer**.                                                                                                                                                    |
| A yellow box, "The D2 renderer URL is not usable"               | The setting holds something that is not a plain `http(s)` URL, or has a user name, query or fragment. The box says which.                                                                                    |
| A yellow box, "This D2 diagram did not render", with the source | The renderer answered with an error or did not answer. Check the renderer is running, the URL is right, and the diagram compiles. Kroki returns its own error picture instead, so you see the message there. |
| "This D2 diagram is too large to send in a URL"                 | Split the diagram.                                                                                                                                                                                           |
| Every diagram fails after a Docker start on a Mac               | The image is `linux/amd64` only. Add `--platform linux/amd64`.                                                                                                                                               |
| Slow first diagram, then fast                                   | The first request runs the D2 compiler. The renderer caches answers, and the preview asks again only for the diagram you changed.                                                                            |

To see a compiler message, paste the source into the [D2 playground](https://play.d2lang.com), or run `d2 validate diagram.d2` if you have D2 installed. The local container's own error reply is not easy to read from a command line.

## Related Projects

- **[d2-renderer](https://github.com/kanad13/d2-renderer):** the Docker image behind the local option. It wraps the D2 compiler in a small HTTP service, speaks the Kroki address format, and includes a runbook and setup script that deploy it to Google Cloud Run from GitHub Actions.
- **[d2-architect](https://github.com/kanad13/coherent-output/tree/main/skills/d2-architect):** an agent skill that adds a verified D2 diagram, laid out with TALA, under every heading of a document without touching the existing text. This preview draws what it writes.
